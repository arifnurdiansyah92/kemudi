# Bahasa Indonesia and English

Kemudi's interface is bilingual from day one. Delivery teams think in English
agile terms; client stakeholders (directors, BUMN and government project
officers) are more at home in Indonesian, and for them it should read as built
for them, not translated for them.

## How it works in `apps/web`

- [i18next](https://www.i18next.com/) with `react-i18next`. Setup is in
  `src/i18n/`; strings live in `src/locales/<lang>/<namespace>.json`.
- English is the source of truth for key types: a key that isn't in
  `src/locales/en/*.json` fails `pnpm typecheck`. `src/i18n/resources.test.ts`
  fails when `id` and `en` disagree on keys or an Indonesian string is empty.
- `pnpm lint` fails on hard-coded UI text in JSX (text and the attributes
  people read: `title`, `placeholder`, `aria-label`, `alt`, `label`, …) and on
  `toast.*('literal')`. Strings outside JSX (zod messages, label maps, toasts
  built in hooks) aren't caught by lint; translate them anyway.
- **Language choice**: the signed-in user's Taiga `lang` decides (so emails
  from kemudi-back follow it), then this device's last choice, then the
  browser. The ID/EN switch (sidebar user menu, Settings → Appearance) saves
  to the user. Per-workspace defaults and the client portal's own language
  come with those features.
- **Formats**: use `src/i18n/format.ts` (`useFormat()` in components), never
  `date-fns` `format` or `toLocaleString` directly for display:
  `date` → 11 Nov 2026, `dateRange`, `timeAgo`, `number` → 1.000,50 / 1,000.50,
  `rupiah` → Rp1.500.000, `time` → 14.05 WIB (WIB/WITA/WIT for Indonesian zones).
  ISO strings sent to the API (`yyyy-MM-dd`) are not display text; keep them.

## Namespaces

| Namespace  | Covers                                                                 |
| ---------- | ---------------------------------------------------------------------- |
| `common`   | Shared actions, statuses, item terms, errors, language names           |
| `shell`    | Sidebar, header, command menu, search, shared components, errors pages |
| `auth`     | Sign in, sign up, password and invitation flows                        |
| `settings` | Your own settings (profile, password, notifications, appearance)       |
| `home`     | Home, projects, discover, profile, notifications, timeline, team       |
| `backlog`  | Backlog, sprints, taskboard, burndown                                  |
| `board`    | Kanban, issues, epics, filters and saved filters                       |
| `item`     | The item sheet and its fields, comments, attachments                   |
| `pages`    | Wiki and importers                                                     |
| `admin`    | Project settings                                                       |

Reuse `common` keys (`t('common:actions.save')`) before adding a new one.

## Writing strings

- Keys are camelCase, nested by screen or component:
  `backlog:sprint.closeDialog.title`. Name the meaning, not the words.
- Interpolate, never concatenate: `t('backlog:sprint.points', { count })`,
  `"{{done}} of {{total}} done"`. Word order differs between languages.
- Plurals: English needs `_one` and `_other`; Indonesian only `_other`
  (the key test accounts for this). Indonesian doesn't pluralise by suffix:
  "3 tugas", not "3 tugas-tugas".
- Sentences with links or bold inside use `<Trans>` with named components.
- Leave room: Indonesian labels often run 20–40% longer than English. Don't
  fix widths on buttons, tabs or table headers.

## Indonesian style

- Address the reader as **Anda**, semi-formal. No "kamu", no "loe".
  Polite imperatives: "Simpan perubahan", "Silakan coba lagi".
- Sentence case, same as English. Short and direct; enterprise, not stiff.
- No machine translation shipped as-is. Every Indonesian string gets a
  native speaker's review before release.

## Not in `apps/web`

Emails and notifications come from kemudi-back
(`services/kemudi-back/taiga/locale/id`), not the web UI; check its
Indonesian coverage separately.
